# Observability for AI agents in Microsoft Foundry: experiment code and data

Test set, configurations, run records and analysis scripts for the paper "Why did my agent do that? Observability for AI agents in Microsoft Foundry" by Bojan Ivanovski, Miodrag Cekikj and Fisnik Doko (CiiT 2027).

## The experiment

A three-agent support desk for a fictional store runs on Foundry Agent Service. A triage agent hands each question to a policy agent (File Search over three policy documents) or an order agent (two function tools on a simulated order system).

Each of three faults is injected in the `before` condition and fixed in the `after` condition:

| Fault (paper) | Code name | `before` | `after` |
|---|---|---|---|
| F1 missing lookup | `mistake1` | "You can use the policy documents" | "Always search the policy documents", and say so if they don't cover it |
| F2 lost order ID | `mistake2` | the order agent gets only the triage summary | it also gets the customer's message and is told never to guess an ID |
| F3 bare error | `mistake3` | the tool returns `Error` while the order system is down | an actionable error text, "do not retry", never the same call more than twice |

40 questions (12 policy, 12 order, 8 outage, 8 controls), 5 runs each, 2 conditions: 400 conversations per agent model. The models are GPT-5 mini (gpt-5-mini 2025-08-07) and GPT-4.1 mini (gpt-4.1-mini 2025-04-14), so 800 conversations in total. Every conversation was traced to Application Insights with sampling off.

The exact instructions, tool texts and handoff of both conditions are in `src/config.py`. `results/conditions.generated.md` prints them side by side.

The paper calls the judges "original" and "full-context". In the files they're judge v2 (`answer_correct`) and judge v3 (`answer_correct_v3`). `b5_numbers.md` compares the recomputed numbers with an earlier draft of the paper, so its "Paper" column can differ from the final text.

`results/CHANGELOG.md` records every decision with its date and reason, and marks each step taken after the results were seen as post hoc. Read it before the result files.

## Human audit

Two authors label a stratified sample of 40 answers blind. The instructions are in `results/audit/INSTRUCTIONS.md`. The labelled sheets, the key and the agreement scores get added here once both labellers are done (`python -m src.audit score ...`).

## Reproducing

The offline tests need no Azure account:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest -q
```

The analyses run from the files in `results/`, also without Azure. For example:

```bash
python -m src.analyze_prereg results/main.graded.jsonl --trace-check results/main.trace_check.csv \
    --foundry results/main.foundry_eval.jsonl --judge3 results/main.judge3.jsonl --out results/rerun/prereg
python results/paper/v3_checks/b5_recompute.py
```

A new run needs an Azure subscription with quota for gpt-5-mini (two deployments, agent and judge) and, for the second arm, gpt-4.1-mini. Copy `.env.example` to `.env` or let the deploy script write it:

```bash
./infra/deploy.sh <resource-group> swedencentral <prefix>
python -m src.setup_resources
python -m src.run_experiment --reps 5 --out results/main.jsonl
AGENT_TAG=gpt41mini AGENT_MODEL_DEPLOYMENT=gpt-4.1-mini-agent python -m src.setup_resources
AGENT_TAG=gpt41mini AGENT_MODEL_DEPLOYMENT=gpt-4.1-mini-agent python -m src.run_experiment --reps 5 --out results/main_gpt41mini.jsonl
./scripts/after_runs.sh
```

Write new runs to new file names, so the original records stay as they are. gpt-5-mini is a reasoning model and accepts no `temperature`. The Foundry SDKs changed often in 2025-2026; every SDK call is in `src/foundry.py`, the one place to adapt.

## What this copy leaves out

Run logs, partial files from interrupted runs, paper drafts and internal working notes. In `results/CHANGELOG.md` the name of an unrelated Azure project whose capacity was briefly lent to the judge is replaced with a description. The spans keep Foundry's agent object IDs (`assistant-...`); they don't work without access to the original Azure project. `PAPER_NOTES.md` is a working note from 17 Nov 2026, written before the paper, and the paper replaces it.
